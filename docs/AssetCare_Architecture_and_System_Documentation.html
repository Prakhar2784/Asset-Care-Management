1. Executive Summary

AssetCare is an enterprise-grade, multi-tenant IT Asset Management (ITAM) and Asset Care Lifecycle Management System. It is engineered to solve critical operational inefficiencies that growing companies and enterprises face when tracking physical hardware, assigning devices to personnel, handling equipment breakdowns, managing vendor service contracts (AMCs), tracking warranties, and maintaining statutory audit compliance.

The platform operates under a dual-delivery model: it functions as a highly scalable multi-tenant Cloud SaaS platform and can also be distributed as a standalone, zero-external-dependency Windows desktop/intranet application. Organizations subscribe to annual commercial tiers (Home User, MSME, or Large Scale), gain access to dedicated isolated workspaces, and onboard their IT teams, department heads, technicians, and employees.

Key Business Capabilities Implemented
  • End-to-End Asset Lifecycle Tracking: Procurement, asset tagging (QR code), departmental allocation, custodian assignment, depreciation, and decommission.
  • Integrated Maintenance & Helpdesk: SLA-governed ticketing, repair workflow escalation, external service center management, and cost tracking.
  • Strict Multi-Tenant Data Enclosure: Complete logical and cryptographic isolation between tenant databases and collections.
  • Automated Commercial Billing & Payments: Automated GST invoicing (CGST/SGST/IGST), coupon discount engine, Razorpay checkout integration with HMAC SHA256 webhook reconciliation, and 365-day annual license enforcement.
  • Platform Super Admin Console: Centralized tenant monitoring, revenue analytics, company activation/deactivation controls, coupon creation, and 360° company data audit.

10. Multi-Tenant Architecture & Isolation

Tenant isolation is enforced in every layer of the software stack:

  • Identification: When a user logs in, their JWT contains their immutable tenantId. For API calls, the frontend automatically transmits the X-Tenant-Id header.
  • Mongoose Tenant Plugin: All tenant-scoped Mongoose queries automatically inject { tenantId: req.tenantId } into find, findOne, update, and count filters.
  • Cross-Tenant Leakage Prevention: Even if a malicious user alters an ID parameter in a URL, the query will return null (404) because the record’s tenantId will not match the authenticated session's tenant token.
  • Super Admin Isolation Bypass: Platform Super Admins have explicit global scope for administrative oversight while retaining strict tenant auditing.

17. Checkout, Upgrade & Downgrade Architecture

Upgrade Behavior (Immediate Prorated Transition)

When an organization upgrades (e.g. Home User → MSME or MSME → Large Scale), the system processes the upgrade immediately upon payment verification, raises resource caps instantly, and initializes a fresh 365-day term while recording the transition in SubscriptionHistory.

Renewal Behavior (Cycle Extension)

Renewing the current active plan extends the subscription for an additional 365 days from the current expiry date without interrupting service or resetting asset registries.

Downgrade Policy

Current System Rule: Immediate Downgrades Are Blocked

Immediate downgrading to a lower plan tier (e.g., Large Scale with 120 assets attempting to downgrade to Home User with a 20-asset limit) is blocked with HTTP 400 (DOWNGRADE_NOT_ALLOWED) to prevent immediate data truncation or orphaned assets.

Scheduled Downgrade: Scheduled downgrade at the end of the billing term is not implemented in the current v1.0.0 release.

21. GST & Billing Calculation Engine

All billing calculations are strictly rounded to 2 decimal places (Math.round(n * 100) / 100) to eliminate floating-point artifacts:

Mathematical Formula
  1. Base Amount: Plan Price (P)
  2. Discount Amount: D = min(CalculatedDiscount, MaxDiscount)
  3. Taxable Base: T = P - D
  4. GST Computation:
    • If Customer State == Vendor State (Rajasthan): CGST (9%) = T * 0.09 + SGST (9%) = T * 0.09
    • If Customer State != Vendor State: IGST (18%) = T * 0.18
  5. Final Grand Total: Total = T + GST

22. Razorpay Payment Architecture

Payment transactions follow a 2-step cryptographically verified order flow:

Figure 6: Razorpay Payment Verification & Activation Protocol

HMAC SHA256 Signature Verification: The server computes crypto.createHmac('sha256', secret).update(order_id + '|' + payment_id).digest('hex'). If the computed signature matches the client's payload, the invoice is set to 'Paid' and the tenant's license is activated.

25. Company Deactivation & Access Control

When a Super Admin deactivates a company:

  1. The master Tenant.isActive flag is flipped to false in MongoDB.
  2. All subsequent API requests with that tenant's JWT are intercepted by authMiddleware.js, which detects the deactivated state and immediately returns HTTP 403 Forbidden (COMPANY_DEACTIVATED).
  3. The frontend Axios response interceptor captures the 403 response, purges the client local storage session, and redirects the user to /login?deactivated=1.

42. Architectural Conclusion

The AssetCare architecture delivers a balance of developer velocity, enterprise security, and operational reliability:

  • Modular Decoupling: Frontend and backend communicate strictly over authenticated RESTful contracts, allowing independent scaling and headless operations.
  • Bulletproof Isolation: Multi-tenant design prevents cross-customer leakage at both the query level and middleware level.
  • Server Authoritative Billing: All financial and entitlement logic is computed server-side, eliminating financial tampering risks.
  • Deployment Flexibility: The codebase seamlessly compiles into both cloud-hosted SaaS infrastructure and zero-config Windows desktop packages.
